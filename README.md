# 档案元数据核对台

`sologsb-1020` 是一个用于口述史与手稿档案元数据比对的本地优先前端工作台，使用 Qwik、TypeScript 和 Qwik UI 构建。

## 功能

- 导入 A / B 两组记录，支持 JSON 数组、制表符和竖线分隔文本。
- 按标题、日期、人物、地点和编号加权匹配，显示综合分数与判断依据。
- 键盘密集复核：J/K 移动、Enter 合并、C/R 确认或忽略，支持批量操作。
- 合并时逐字段并排展示 A / B 来源，每个冲突字段可单独保留或拼接。
- 保存原始记录、字段来源选择、合并结果和忽略动作，形成完整审计轨迹。
- 支持撤销重做、离线 localStorage 保存和 JSON 核对包导出。
- 大量记录采用分批窗口渲染，匹配计算限制每条记录的候选数，避免一次挂载全部行。
- **目录快照对账**：馆藏目录管辖编号、权利与记录存活，本机管辖匹配结论、字段选择与审计轨迹。

## 技术栈

- Qwik 1.20
- TypeScript 5.9
- Qwik UI Headless `@qwik-ui/headless`
- Vite 7

## 开发

```bash
npm install
npm run dev
```

开发服务使用 Vite 默认端口，不在源码中硬编码宿主端口。

## 生产构建

```bash
npm run build
npm run preview
```

静态产物输出到 `dist/`。

## Docker

```bash
docker build -t sologsb-1020 .
docker run --rm -p 10020:80 sologsb-1020
```

nginx 在容器内监听 `80`，宿主端口 `10020` 由根端口表或运行命令映射。

## 数据说明

记录和审计轨迹保存在当前浏览器。导入新记录后自动重新计算候选匹配，但不会自动确认或覆盖任何字段。

## 目录快照同步

顶栏「目录同步」打开对账中心。同步协议分两段，顺序固定：

1. **先提交本机变更**：把上次基线之后产生的匹配结论与合并字段选择打成批次（每批 3 条），批次 id 由决策内容稳定生成。中断时保留发送计划与已成功回执，重试同一批时目录端按批次 id 幂等去重，绝不重复写入；也可放弃本轮但保留已送达回执。
2. **再取新快照并三方对账**（以基线快照为共同祖先，纯函数实现于 `src/sync/reconcile.ts`）：
   - 目录单方面修订的编号 / 权利 → **自动应用**（不触碰本机合并结论）；
   - 目录与本机合并都改了同一字段且取值不同 → **待裁项**，可选保留本机 / 采用目录 / 拼接双方；
   - 目录移除记录而本机已完成合并（含被吸收的任一来源编号）→ **存活待处理**，本机保留（标记「目录已移除」）或按目录删除；目录移除且本机未合并 → 自动删除；
   - 目录新增记录 → 待导入，导入后重算匹配且不丢已有结论。
3. 所有裁决完成后才能应用并把基线推进到新版本；全过程（提交、拉取、自动应用、裁决、存活处理、导入）写入审计轨迹，支持撤销。
4. 对账报告可随时导出为 JSON（含基线、新快照、自动项、待裁项、裁决选择与回执）。

`src/sync/catalogServer.ts` 用 localStorage 模拟馆藏目录服务，内置延迟、手动「模拟发送中断」和「弱网（目录已写入但回执丢失）」开关，可直接演示断点续传与幂等重试；`src/sync/demoRevision.ts` 一键发布覆盖全部对账分支的目录离线修订。接入真实目录时只需把该文件替换为同名 HTTPS 客户端。
